# Command reference

[Back to the README](../README.md)

```text
diz [flags] <list|create|update|restore|serve> [args...]
```

Flags go before the command. Commands use the local Docker daemon as the image source unless `-fromzip` points to an existing archive. The Docker client uses environment variables such as `DOCKER_HOST`, `DOCKER_TLS_VERIFY`, and `DOCKER_CERT_PATH`.

## Select image tags

Use exact references or quoted glob patterns:

```sh
diz list 'alpine:*'
diz list '*' '-example/experimental:*'
diz create images.diz alpine:3.24 nginx:alpine
```

Patterns are evaluated in order. A leading `-` excludes matches; a later matching pattern can include them again. A first negative pattern starts from all tags. With no patterns and no tag file, no tags are selected.

`-pull` accepts exact image references, not globs. It pulls missing images; it does not refresh a tag that already exists locally. Run `docker pull` first when you need the current upstream version of an existing tag.

## list

```sh
diz list '*'
diz -fromzip images.diz list '*'
```

Print matching image tags, one per line. Listing an archive does not contact Docker.

## create

```sh
diz create images.diz 'alpine:*'
diz -pull create images.diz alpine:3.24 nginx:alpine
diz -fromzip images.diz create selected.diz 'alpine:*'
```

Write a new ZIP archive containing the selected images. Existing output files are overwritten. When copying from an archive, use a different output path from the input.

ZIP entries shared by filename are included once. The archive also contains image manifests and a content-hash index; it is not an OCI image layout or a tar stream for `docker load`.

## update

```sh
diz update images.diz next.diz 'alpine:*'
diz -fromzip newer.diz update images.diz next.diz 'example/app:*'
```

Seed a new archive with the old archive's images, replace selected tags from the configured source, and retain the other tags. Entries carried over from a ZIP archive are copied in compressed form.

The output must be a different file from **both** input archives. Updating is a new-file operation; it does not patch an archive in place.

## restore

```sh
diz -fromzip images.diz restore '*'
diz -fromzip images.diz restore 'alpine:*'
```

Stream the selected images into Docker's image-load API. A running Docker daemon is required. Errors reported in Docker's load response cause the command to fail.

## serve

```sh
diz serve images.diz
```

Serve images from the archive until interrupted with Ctrl+C. A Docker daemon is not needed to run the server. The archive stays open for the lifetime of the process.

For an archive containing `alpine:3.24`, a local Docker client can use:

```sh
docker pull localhost:5000/alpine:3.24
```

The server listens on `:5000` on all interfaces. The listen address is currently fixed, and the server provides neither TLS nor authentication. Keep it within a trusted network. Remote Docker clients may require registry trust configuration; see Docker's [registry security documentation](https://docs.docker.com/reference/cli/dockerd/#insecure-registries). For broader access, use an authenticated TLS proxy or a full registry service.

Useful endpoints:

| Path | Result |
| --- | --- |
| `/v2/` | Registry version check |
| `/v2/manifests` | Images recorded in the archive, as JSON |
| `/v2/<repository>/manifests/<tag>` | Docker schema 2 manifest |
| `/v2/<repository>/manifests/sha256:<digest>` | Manifest by its diz registry digest |
| `/v2/<repository>/blobs/sha256:<digest>` | Config or layer content |
| `/get/<path>` | A file from the ZIP archive |
| `/get/<directory>/` | Directory contents streamed as a ZIP archive |

Repository names can contain namespaces, such as `team/app`. These are pull and inspection endpoints; the server does not support pushing images.

## Tag files

`-tagfile` appends image references from a file to any references passed on the command line. Each line can contain a reference, a `key=reference` assignment, or a comment:

```text
# Exact image references
base=alpine:3.24
web=nginx:alpine # served by the demo environment
```

A checked-in [example file](../examples/images.txt) is available. Copy it before experimenting with rewriting flags:

```sh
cp examples/images.txt images.txt
diz -pull -tagfile images.txt create images.diz
```

After archive creation, `-digest` can rewrite matching references to their digest, and `-registryAddress` can point them at the registry serving the archive:

```sh
diz -pull -tagfile images.txt -digest -registryAddress localhost:5000 create images.diz
```

This edits `images.txt` in place, preserving keys, comments, whitespace, and line endings. Keep the original file if you also need the upstream tags.

The rewritten digests identify **the manifests generated by diz**, which can differ from the source registry's digests. Use them with the registry serving that archive. When no tag file is configured, these options print normalized tag/digest pairs instead of editing a file.

An unreadable tag file is currently ignored when collecting input references. Verify the path and inspect the resulting archive with `diz -fromzip images.diz list '*'`.

## Flags

| Flag | Default | Purpose |
| --- | --- | --- |
| `-fromzip <file>` | Local Docker daemon | Read images from a diz archive |
| `-tagfile <file>` | None | Add image references from a text file |
| `-pull` | `false` | Pull missing exact references before saving |
| `-level <n>` | `-1` | Compression level: `0` for no compression, `1`–`9` for speed/size tradeoffs, `-1` for the compressor default |
| `-digest` | `false` | Rewrite matching tag-file references to diz manifest digests after create/update |
| `-registryAddress <host:port>` | Unchanged | Rewrite the registry in matching tag-file references after create/update |
| `-h` | — | Print commands, examples, and flags |

## Troubleshooting

**No tags are listed.** Pass a pattern such as `'*'`; no selection is implied. Check the input archive or the local Docker image list.

**Cannot connect to Docker.** Start Docker Engine and check its environment variables. Archive listing, copying, and serving work without a running daemon, but an invalid Docker client configuration can still prevent the CLI from starting.

**The registry cannot bind to port 5000.** Another process is already using the fixed port. See [issue #2](https://github.com/JohanLindvall/diz/issues/2) for configurable listening addresses.

**A command fails on an image archive.** Include your Docker version, image-store backend, command, and error output in a [bug report](https://github.com/JohanLindvall/diz/issues/new?template=bug_report.yml). Share public sample images or sanitized fixtures when possible.
